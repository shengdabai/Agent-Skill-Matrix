# Resume STAR Optimizer（简历 STAR 优化技能）

把简历顾问的隐性判断固化成可执行 SOP：用户给一段流水账式工作经历，技能按五步流程将其拆解、量化、强化，输出专业的成果型 bullet points。

## 这个技能在做什么（先读这段，建立心智模型）

普通人写简历的通病：写"做了什么"（职责描述），而不是"达成了什么"（成果证明）。
HR 和 ATS（简历筛选系统）想看的是：**动作 + 量化结果 + 业务影响**。

本技能的核心转换：

> 流水账：「负责公司的微信公众号运营工作」
> 成果型：「独立运营企业微信公众号，6 个月内将粉丝量从 8000 提升至 3.2 万（+300%），单篇平均阅读量提升 2.4 倍」

技能不会替用户编数据。缺数字时**主动追问用户**，问不到就用结构化定性表达 + 标注待补，绝不虚构。

## 核心模型：STAR

| 字母 | 含义 | 在 bullet 里的作用 |
|------|------|------------------|
| **S** Situation | 背景/情境 | 简历里通常压缩或省略，只在必要时一句带过 |
| **T** Task | 任务/目标 | 你要解决什么问题、负责什么 |
| **A** Action | 行动 | 你**具体**做了什么（强动词开头，体现主动性与方法） |
| **R** Result | 结果 | **量化**成果 + 业务影响（最重要，必须有数字或可验证事实） |

简历 bullet 的黄金结构：**强动词 + 做了什么（Action）+ 量化结果（Result）+ 业务价值**。
Situation/Task 通常融入或省略，把宝贵篇幅留给 Action 和 Result。

## 五步流程（流程型 + 关键步骤人工确认）

> 重要：第三步「量化追问」是**强制人工确认点**。没有数字时必须停下来问用户，不得自行编造或跳过。

### 第一步：检查输入（够不够具体）

读用户给的经历，判断信息密度：

- **够具体**（有动作、有对象、隐含可量化点）→ 进入第二步。
- **太空泛**（如"负责相关工作""协助团队""参与项目"且无任何细节）→ **先追问**，不要硬拆。追问示例：
  - 「这段经历你具体做了哪几件事？能举 1-2 个最有代表性的吗？」
  - 「这个项目的目标是什么？你在其中承担了什么角色？」
  - 「有没有可以体现成果的数字（人数 / 金额 / 比例 / 时间 / 频次 / 排名）？」

判断空泛的信号词清单见 `references/star-examples.md` 的"空泛信号词"一节，需要时读取。

### 第二步：STAR 拆解

把经历拆进 STAR 四要素（内部分析，不一定全部进最终 bullet）：

- 提取 **Action**：用户具体做了哪些动作？每个动作配一个候选强动词。
- 定位 **Result**：哪里有结果？是否已量化？没量化的标记为"待量化"。
- 压缩 **Situation/Task**：能省则省，只保留让 Action/Result 站得住的最小背景。

输出一份"拆解草稿"给用户看（可选），让用户确认理解无误。

### 第三步：量化追问（强制确认点，不编造）

对每个"待量化"的结果，**主动向用户提问**，引导其回忆数字。常用追问维度：

- **规模**：服务多少人 / 管理多大预算 / 覆盖多少账号？
- **变化**：从多少提升到多少？增长 / 下降百分比？
- **效率**：节省多少时间 / 提速多少 / 减少多少成本？
- **频次**：每周 / 每月做多少次？产出多少篇 / 个 / 单？
- **排名/对比**：团队第几？同比 / 环比？超出目标多少？

完整量化追问清单见 `references/star-examples.md` 的"量化追问清单"。

**红线**：
- 用户给不出准确数字 → 引导给区间或量级（"大概 3-5 万""翻了一倍左右"），并在 bullet 里如实用约数。
- 用户完全无法提供 → **不编造**。改用定性强表达（"显著提升""主导上线"），并在交付时**明确标注**「此条缺量化数据，建议补充真实数字以增强说服力」。
- 绝不凭空写"提升 30%""营收百万"这类未经用户确认的数字。

### 第四步：动词强化 + ATS 关键词对齐

1. **动词强化**：把弱动词（负责、参与、协助、做、帮）换成职能匹配的强动词。
   - 替换库见 `references/action-verbs.md`（按领导/分析/创造/沟通/执行等分类，含弱→强对照）。
2. **ATS 关键词对齐**：如果用户提供了目标 JD（职位描述），提取 JD 高频关键词/硬技能，自然融入 bullet（不堆砌）。
   - 各行业关键词示例与 JD 匹配方法见 `references/ats-keywords.md`。
   - 用户没给 JD → 用该职能的通用核心关键词，并提示「提供目标 JD 可显著提升匹配度」。

### 第五步：输出 bullet + 自检

按"强动词 + Action + 量化 Result + 业务价值"输出 3-5 条 bullet（或与原经历数量相当）。每条输出后过一遍自检清单：

- [ ] 每条以强动词开头？
- [ ] 每条有量化结果（或已明确标注"缺数据待补"）？
- [ ] 是成果导向而非职责罗列？
- [ ] 无假大空表述（见禁止清单）？
- [ ] 无编造数字（所有数字都经用户确认）？
- [ ] 关键词与目标职能/JD 对齐？
- [ ] 单条长度适中（1-2 行，约 15-30 字中文 / 1-2 行英文）？

未过自检 → 回到对应步骤修正后再交付。

## 禁止清单（约束型核心）

**四类必须禁止**，正面 vs 反面对照：

### 1. 禁假大空（无信息量的职责套话）
- ✗ 「负责公司相关运营工作」「协助完成各项任务」「参与团队日常事务」
- ✓ 「主导小红书账号矩阵从 0 搭建至 5 个账号，累计粉丝 12 万」

### 2. 禁无量化（只说做了不说结果）
- ✗ 「优化了产品的注册流程」
- ✓ 「重构注册流程，将注册转化率从 41% 提升至 63%，月新增用户 +2200」

### 3. 禁主观夸大（自封形容词、不可验证的吹嘘）
- ✗ 「具备超强的领导力，是团队不可或缺的核心」
- ✓ 「带领 6 人小组在 3 周内交付 V2.0，提前 1 周达成里程碑」

### 4. 禁编造数字（用户未提供 / 未确认的数据）
- ✗ 用户没说数据，技能擅自写「提升 35%」「服务上千客户」
- ✓ 用户确认过的数字才写；无数据则定性表达 + 标注「建议补充真实数据」

禁止清单的更多反面例子和改写见 `references/star-examples.md`。

## 踩坑点

- **空泛输入硬拆**：经历本身没信息，强行套 STAR 会编出假内容。正解：第一步先追问，拿到细节再拆。
- **量化追问变审讯**：一次抛 10 个问题会吓退用户。正解：一次问 2-3 个最关键的，循序渐进。
- **强动词堆砌/不匹配职能**：技术岗用一堆"领导力"动词、管理岗全是"编码"动词都跑偏。正解：按 `references/action-verbs.md` 匹配职能选词。
- **ATS 关键词硬塞**：把 JD 词生硬堆进 bullet（关键词作弊），ATS 和 HR 都会反感。正解：自然融入，读起来仍是通顺的成果句。
- **过度量化失真**：给每件小事都强行配数字，反而显假。正解：抓最有代表性的 2-3 个成果重点量化。
- **把约数写成精确数**：用户说"大概一万多"，别写成"10,247"。正解：尊重用户给的精度，约数就用约数。
- **中英混排不统一**：同一份简历数字格式、动词时态忽中忽英。正解：先确认目标语言，全篇统一。
- **省略 Situation 过头**：完全无背景导致成果看不懂含金量。正解：必要时一句话交代背景，让结果可被理解。

## 安全（简历含个人隐私）

简历是高敏感个人信息载体。本技能处理时：

- **隐私边界**：本 Skill 不主动调用外部工具或写入文件；数据如何传输与留存取决于宿主平台。先删除不必要的身份证号、住址、电话等信息；仅在已核验宿主条件时称为本地处理。
- **不索取敏感字段**：优化 bullet 不需要身份证号、家庭住址、银行卡、完整电话/邮箱。若用户粘贴了，提示其在对话外的存档中谨慎保管，本流程只需工作经历正文。
- **脱敏建议**：如用户要把对话记录或产出存档/分享，提醒先移除真实姓名、联系方式、雇主敏感内部数据（如未公开营收、客户名单）。
- **不编造可被背调核实的信息**：所有数字、头衔、时间必须真实，编造在背景调查中会导致 offer 撤销。这既是质量底线也是对用户的保护。
