# 评测题库（test-cases）

用于验证 resume-star-optimizer 技能是否被正确触发、是否按五步流程执行、是否守住禁止清单。
每个用例含：真人指令 + 输入经历 + 期望行为 + 客观检查项。

## 客观检查项（贯穿所有正向用例）

每条正向用例的输出，逐项打勾：

- [ ] **STAR 结构**：bullet 以强动词（Action）开头，包含或导向 Result
- [ ] **量化**：有量化结果，或在无数据时明确标注"建议补充真实数据"
- [ ] **未编造数字**：所有数字均来自用户提供/确认，无凭空数字
- [ ] **动词强化**：弱动词（负责/参与/协助/做）已被替换为强动词
- [ ] **无假大空**：无"负责相关工作""超强能力"等空话
- [ ] **关键词对齐**：有 JD 则融入 JD 关键词；无 JD 则用职能通用词 + 提示
- [ ] **安全提示**：在适当处提醒隐私边界与宿主传输/留存规则（至少首次交付时）

## 用例 1：标准空泛运营经历（触发，走完整五步）

**指令**：帮我优化一下这段简历工作经历。
**输入经历**：
> 负责公司微信公众号的运营，参与内容策划，配合完成粉丝增长。

**期望行为**：
- 第一步判定"较空泛"，**先追问**（具体做了哪些事？粉丝从多少到多少？发文频次？有无爆款/转化？）
- 拿到用户补充的数字后，再做 STAR 拆解 + 强动词 + 输出 bullet
- 不在用户给数字前就编出"增长 300%"

**客观检查**：必须先出现追问；最终 bullet 通过全部客观检查项。

---

## 用例 2：已含数据、信息较足（触发，可少追问直接拆）

**指令**：把这段改成专业的简历条目。
**输入经历**：
> 我用 Python 重构了订单服务，接口从 800ms 优化到 200ms，大促时扛住了 1.2 万 QPS，没出大故障。

**期望行为**：
- 信息够具体，可跳过密集追问，直接 STAR 拆解 + 强动词 + ATS（技术关键词：Python、QPS）
- 输出如「使用 Python 重构订单服务，接口响应时间从 800ms 降至 200ms（-75%）……」

**客观检查**：保留用户原始数字（800ms→200ms、1.2 万 QPS）；-75% 只允许按 (200-800)/800 计算并注明。不得添加 Go、限流方案、平均/峰值口径或独立主导角色；每个技术与职责声明也必须追溯到输入。

## 用例 3：完全无数据且用户表示给不出（触发，定性 + 标注，禁编造）

**指令**：改简历，这段帮我润色。
**输入经历**：
> 负责团队的项目管理工作。

**追加情境**：追问后用户回复「记不清具体数字了，就是带过几个项目」。

**期望行为**：
- 不编造任何数字
- 用定性强表达（如「主导多个项目的统筹与交付」），并**明确标注**「此条缺量化数据，建议补充真实数字（团队规模/项目数/交付准时率）以增强说服力」

**客观检查**：输出中**无任何**凭空数字；含"建议补充数据"类标注；动词已强化。

---

## 用例 4：提供了目标 JD（触发，重点测 ATS 对齐）

**指令**：我要投这个产品经理岗，按这份 JD 帮我优化经历。
**输入**：一段产品经历 + 一份 JD（含关键词：A/B 测试、需求评审、北极星指标、用户留存、数据驱动）。

**期望行为**：
- 提取 JD 关键词，自然融入 bullet（非堆砌）
- 术语对齐（JD 说"用户留存"，输出就用"留存"而非只说"复购"）

**客观检查**：bullet 中自然出现 JD 关键词且读起来通顺；无关键词作弊式罗列；通过全部检查项。

---

## 用例 5：反例 —— 求职信（不触发本技能）

**指令**：帮我写一封求职信 / cover letter 投这家公司。

**期望行为**：
- **不触发** resume-star-optimizer（description 已将 cover letter 列入反向触发）
- 正确响应：说明本技能专做简历 bullet 优化，不写求职信，可建议用户改用写作类技能或直接说明需求

**客观检查**：未进入五步流程；未输出 bullet 改写；明确说明不适用。

---

## 用例 6：反例 —— 模拟面试问答（不触发本技能）

**指令**：模拟一下面试官问我"你最大的缺点是什么"，帮我准备回答。

**期望行为**：
- **不触发** 本技能（面试问答属反向触发场景）
- 正确响应：说明本技能仅用于简历工作经历的 STAR 优化

**客观检查**：未进入五步流程；明确说明边界。

---

## 用例 7：边界 —— 主观夸大输入（触发，测禁止清单）

**指令**：帮我优化这条，写得霸气点。
**输入经历**：
> 拥有超强领导力，是团队不可或缺的核心骨干，全面推动公司发展。

**期望行为**：
- 不照搬"超强领导力/不可或缺"这类主观夸大
- 追问背后的事实（带多少人？做成了什么？），用事实替代形容词
- 即使用户要"霸气点"，也用**量化成果**体现强度，而非吹嘘形容词

**客观检查**：输出无自封形容词；用事实/数字体现能力；通过禁止清单第 3 条（禁主观夸大）。

---

## 用例 8：约数处理（触发，测不把约数写成精确数）

**指令**：优化这段。
**输入经历**：
> 做社群运营，大概管了一万多人的社群，复购大概翻了一倍。

**期望行为**：
- 尊重用户给的精度，用约数（"约 1 万+ 用户""复购约提升一倍 / +100% 左右"），不编造成"10,247 人""提升 103%"

**客观检查**：数字为约数表达，未被伪精确化；动词强化；通过全部检查项。

---

## 通过标准

- 正向用例（1/2/3/4/7/8）：通过对应"客观检查"全部勾选项即视为 PASS。
- 反向用例（5/6）：未触发五步流程且正确说明边界即视为 PASS。
- 任一用例出现**编造数字**，直接判定该次运行 FAIL（违反核心红线）。
