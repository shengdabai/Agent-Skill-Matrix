# data-report-pro · 数据分析报告

把一份杂乱的 Excel/CSV，变成一份**有结论、有图表、有建议**的专业分析报告。

这是一个**流程型**技能：固化"读数据 → 三阶段分析 → 生成 HTML 报告"的完整工作流，让每一次产出都达到资深数据分析师的水准，而不是简单地把数字罗列出来。

## 何时启动

- 用户上传 `.xlsx` / `.xls` / `.csv` 并说"分析一下""帮我看看""做个报告"
- 用户描述一份数据（投放、销售、运营、财务、用户）并希望得到**洞察与建议**
- 用户想把表格"变好看""做成可视化""出个图文报告"

## 何时**不要**启动（反向触发）

- 只想取某一个单元格的值、算某一列的总和/平均值 → 直接算，别走全流程
- 只想清洗/转换格式（去重、改列名、转 JSON）→ 用数据处理而非分析
- 要查实时数据库/接口 → 本技能只处理静态文件

---

## 工作流总览（必须按顺序）

```
1. 读取数据      → 多工作表/编码/表头判断
2. 三阶段分析    → 理解结构 → 统计概况 → 挖掘发现
3. 组织输出结构  → 摘要/全貌/核心发现/关注/建议
4. 生成 HTML 报告 → 先读 references/，再填数据
```

**关键纪律：先分析出"结论"，再去画图。** 图表是为结论服务的，不是为了好看而堆图。

---

## 第一步：读取数据（给指引，不给死脚本）

数据分析最容易在"还没开始分析"就翻车。读取前先用 pandas（或等价工具）探查，**逐项确认**：

1. **多工作表**：Excel 可能有多个 sheet。先 `pd.ExcelFile(path).sheet_names` 列出所有 sheet，判断哪个是主数据，哪些是说明/字典/汇总。不要默认读第一个。
2. **编码检测**：CSV 常见编码陷阱。中文 CSV 可能是 `utf-8` / `utf-8-sig`（带 BOM）/ `gbk` / `gb18030`。先尝试 `utf-8`，报 `UnicodeDecodeError` 再退回 `gbk`。不要硬编码一种编码。
3. **表头检测**：真实表格的表头未必在第 1 行——上方常有标题行、合并单元格、空行。先 `head(10)` 肉眼看一眼，确认 `header=` 应该取第几行，必要时 `skiprows=`。
4. **分隔符**：CSV 不一定是逗号，也可能是制表符 `\t` 或分号 `;`（欧式导出）。
5. **数据规模**：先看行列数。超大文件（百万行级）先抽样理解结构，再决定是否全量。

> 这一步**不预置脚本**，因为每个文件都不同。原因和"何时该写脚本"见 `scripts/README.md`。

## 第二步：三阶段分析法（核心方法论）

这是本技能的灵魂。**任何报告都必须走完三个阶段，不能跳。**

### 阶段一：理解结构（这是什么数据？）

在算任何数字之前，先回答：

- **一行代表什么？** 一行 = 一次投放？一笔订单？一天的汇总？一个用户？——这决定了所有后续分析的口径。
- **哪些是维度，哪些是指标？**
  - 维度（定性、用来分组）：渠道、板块、地区、日期、品类、性别
  - 指标（定量、可加总/求均值）：消耗、GMV、ROI、退货率、点击量
- **有没有时间列？** 有时间 → 可以做趋势分析。确认时间粒度（天/周/月）和时间跨度。
- **主键/粒度是否唯一？** 是否有重复行？是否需要先按某维度聚合？

输出这一阶段时，用一句话讲清"这是一份关于 ___ 的数据，每行代表 ___，共 ___ 行，覆盖 ___ 时间段"。

### 阶段二：统计概况（数据长什么样？）

对每个关键指标，**不要只看平均值**：

- **均值 + 中位数一起看**：两者差距大 = 分布偏斜 = 有极端值在拉扯平均。中位数更代表"典型情况"。
- **分位数 p25 / p75 / p95**：p95 告诉你"头部到什么程度"，p25/p75 告诉你"大多数落在哪个区间"。
- **零值与缺失**：某列有多少是 0？多少是空？0 和空含义不同（0 = 真的没有，空 = 没记录）。缺失率高的列要在报告里标注，别假装它完整。
- **维度分布**：每个类别各占多少？是否极度不均衡（80% 集中在一个渠道）？

### 阶段三：挖掘发现（哪里不寻常？）

这一步才产生"洞察"。三种武器：

- **异常检测（2 个标准差）**：偏离均值 2 个标准差以上的点，重点看。异常往往是问题或机会。比如某次投放 ROI 是平均的 1/5，或退货率突然飙到 3 倍。
- **相关性（|r| > 0.7）**：两个指标强相关时点出来。注意——**相关不等于因果**，报告里要措辞谨慎（"伴随""相关"而非"导致"）。
- **趋势**：有时间列时，看指标随时间是上升、下降还是波动。**下滑趋势是最值钱的发现之一**，因为它预示未来。

## 分析哲学（决定报告"专业"还是"平庸"）

写报告时反复用这五条自检：

1. **对比产生意义**：单个数字没有意义。"ROI 1.8"无意义，"ROI 1.8，低于整体均值 2.4、低于盈亏线 2.0"才有意义。永远给数字找参照系（均值/上期/目标/同行/盈亏线）。
2. **回答 So What**：每个发现都要追问"那又怎样？"。"A 渠道消耗最高"——所以呢？"所以 A 渠道吃掉 60% 预算却只贡献 30% GMV，建议削减"——这才是洞察。
3. **标题就是结论**：报告的小标题不要写"渠道分析"，要写"B 渠道 ROI 是 A 渠道的 2 倍，预算应倾斜"。读标题就能读懂结论。
4. **异常值是金矿**：不要把异常当噪声删掉。最大的亏损投放、最高退货率的板块，往往藏着最重要的行动点。
5. **警惕虚假精确**：不要写"增长率 23.7184%"。数据本身有噪声，过度精确是假象。该约等于就约等于（"约 24%"）。

## 第三步：组织输出结构

报告正文严格按这个结构组织：

1. **一句话摘要**：整份数据最重要的一个结论。读者只看这句也能抓住重点。
2. **数据全貌**：这是什么数据、多大规模、什么时间段、关键 KPI 总览（用 KPI 卡片）。
3. **核心发现（3-5 条，按重要性排序）**：每条 = `发现（结论式标题）+ 支撑数据 + So What（意味着什么/该做什么）`。每条**至少配一张图**。
4. **值得关注**：数据质量问题、缺失、口径风险、需要进一步确认的疑点。
5. **建议**：基于发现的可执行行动项，最好按优先级排。

> 核心发现控制在 3-5 条。贪多反而稀释重点——宁可 3 条扎实，不要 8 条平庸。

## 图表选择指南

每个核心发现至少配一张图，**图表类型要服务于数据关系**：

| 数据关系 | 图表类型 | 说明 |
|---------|---------|------|
| 类别对比（各渠道消耗） | 柱状图 bar | 离散类别间比大小 |
| 时间趋势（每日 GMV 变化） | 折线图 line | 强调随时间的走向 |
| 占比构成（预算分配） | 环形图 doughnut | 部分相对整体（类别 ≤6 个时才用） |
| 变量关系（消耗 vs GMV） | 散点图 scatter | 看两个连续变量的相关性 |
| 分布（ROI 分布） | 直方图（柱状变体） | 看数值集中在哪个区间 |

**反例（不要犯）**：用饼图/环形图表达时间趋势；类别超过 6 个还硬用环形图（挤成一团看不清，改横向柱状图）。

## 第四步：生成 HTML 报告

报告模板和设计规范已拆分到 `references/`，**按需读取以节省上下文**：

1. **先读 `references/design-brief.md`** —— 确定本次报告的视觉风格定位（杂志风/经济学人/麦肯锡/彭博）与排版、配色、字体方向。
2. **再读 `references/report-template.html`** —— 这是一份完整可用的单文件模板（标题区 + KPI 卡片行 + 发现卡片含图表 + 数据表格），Chart.js 从 CDN 加载，数据以 `report-data` JSON 数据块 嵌入。
3. **可选读 `references/domain-knowledge.md`** —— 当数据属于电商/投放等领域且需要"健康线/预警线"参照时（如 ROI 盈亏线、退货率预警线），加载领域基准来增强 So What 判断。

生成步骤：
- 把分析得到的 KPI、核心发现、图表数据保存为严格 JSON，然后运行 `python3 scripts/render_report.py --data report-data.json --output report.html`。不得手工拼接脚本；生成器负责安全编码并拒绝 NaN/Infinity。
- 每个发现卡片绑定一个 Chart.js 图表（类型按上表选择）
- 标题区写一句话摘要，发现卡片标题写"结论式标题"
- 输出为**单个 `.html` 文件**，确保双击可查看文本与表格；图表需联网（CDN 加载 Chart.js，数据内嵌，不依赖本地服务器读文件）
- 生成后告知用户文件路径

## 踩坑点

- **忽略编码导致中文乱码**：直接 `pd.read_csv` 不指定编码，中文列名/内容变成乱码。必须先探编码（utf-8 → utf-8-sig → gbk）。
- **把饼图用于趋势**：占比图（饼/环）只表达"部分与整体"，绝不能表达"随时间变化"。趋势必须折线图。
- **只看均值被极端值骗**：一两笔超大订单能把平均 ROI 拉得很好看，掩盖大量亏损投放。必须同时看中位数和分布。
- **默认读第一个 sheet**：多工作表 Excel 里第一个常是说明页，主数据在后面。务必先列 sheet。
- **相关当因果**：发现两个指标强相关就写"X 导致 Y"，是分析事故。措辞用"相关/伴随"。
- **图表过载**：一份报告塞十几张图，读者抓不住重点。聚焦 3-5 个核心发现，每个一张图。
- **数据以文件路径而非内联嵌入**：HTML 用 `fetch('data.csv')` 读本地文件，双击打开会因 CORS 失败。必须把数据 `report-data` JSON 数据块 内嵌进 HTML。

## 安全

- **数据本地处理**：本 Skill 不主动外发原始数据；分析过程的数据传输和留存取决于宿主平台。报告数据内嵌；Chart.js 从外部 CDN 加载，敏感报告应在核验依赖后采用完全离线版本。
- **文件覆盖前备份**：生成的报告若与已有文件同名，先确认或自动追加时间戳（如 `report-20260606.html`），不要静默覆盖用户已有文件。
- **不在报告中泄露敏感字段**：若数据含手机号、身份证、邮箱等 PII，分析时聚合处理，报告里不逐行展示原始 PII。
- **只读源文件**：读取 Excel/CSV 时只读不写，不修改用户的原始数据文件。
