# 为什么这里没有预置分析脚本？

本技能**刻意不预置一键分析脚本**。这是方法论决定的，不是偷懒。

## 原因：数据分析的每个环节都需要判断

一个写死的脚本无法回答：
- 哪个 sheet 是主数据？（多工作表）
- 这份 CSV 是什么编码？（utf-8 / gbk / gb18030）
- 表头在第几行？要 skiprows 吗？
- 这一列是维度还是指标？时间列是哪个、什么粒度？
- 哪个数字算"异常"？以什么作为对比基准？

这些判断每个文件都不同。如果用死脚本，要么对大多数文件报错，要么"成功运行但分析全错"——后者更危险。

所以本技能的做法是：**SKILL.md 给出探查指引和方法论，由分析者（你/AI）在 pandas 交互式环境里逐步判断、逐步分析**，而不是套模板。

## 那什么时候**该**写脚本？

当某个步骤是**确定性、可复用、规则清晰**的处理时，写个小脚本是合理的——但它服务于分析，不替代分析判断。典型场景：

1. **日期格式标准化**：源数据里日期混着 `2026/4/1`、`2026-04-01`、`Apr 1 2026`、Excel 序列号。用一段 `pd.to_datetime(..., errors="coerce")` + 格式探测的脚本统一，比手工逐个处理稳。
2. **批量编码探测**：一次要处理多个 CSV 时，写个循环按 `[utf-8, utf-8-sig, gbk, gb18030]` 顺序试读，命中即用。
3. **重复的清洗规则**：去除千分位逗号、把"15%"转成 0.15、统一单位（万→元）等规则明确的转换。
4. **生成报告的最后一步**：把分析好的 `DATA` 对象写入 HTML 模板，可以脚本化（读模板 → 替换 DATA → 写文件）。

## 原则

> 脚本处理"确定性的脏活"，人/AI 负责"需要判断的分析"。
> 先在交互环境里把分析想清楚，再决定哪些步骤值得固化成脚本——而不是上来就写一个大脚本跑全程。

## 安全生成 HTML

完成分析后，把符合模板结构的数据保存为严格 JSON，运行：

```sh
python3 scripts/render_report.py --data report-data.json --output report.html
```

此脚本只负责编码与嵌入，不替代分析。它将 HTML 特殊字符和 Unicode 行分隔符编码，拒绝非有限数值和覆盖既有文件。不要直接拼接 `const DATA` 或手填 script 标签。报告文本与表格可离线；图表仍依赖联网加载 Chart.js，不保证缓存可用。

脚本在创建输出文件前检查 UTF-8 编码；JSON 中含孤立代理字符时会报错，不留下空报告。

报告中的数值必须处于 JavaScript 安全整数范围（绝对值不超过 `9007199254740991`），否则生成器会拒绝，避免浏览器读取时悄悄改变整数。更大的展示值请写成 JSON 字符串；图表需要先换算为可表示的单位，并明确标注单位。

柱状图、折线图和散点图可在每个 `chart` 对象中填写可选字符串 `xTitle`、`yTitle`，例如 `"xTitle": "温度(°C)"`、`"yTitle": "用电量(kWh)"`。省略或填空字符串时不显示对应轴标题；模板不会默认把其他业务的横轴标成消耗。图表画布使用 `chart.title` 作为供辅助技术读取的名称。

每张图至少需要一个数据集，每个数据集至少有一个数据点；柱状图、折线图与环形图的标签也不能为空。环形图只接受非负数，且每个数据集至少有一个正值，避免把负数显示为正的占比或生成空环。柱状图、折线图和散点图仍支持负数。

多个数据集会显示图例，并按数据集区分颜色。单个柱状图仍按类别着色。某张图表初始化失败时，模板会显示说明并继续绘制其他图表，不显示原始错误内容。

每张图后都有「查看图表数据」折叠区，内含带标题和列标题的数据表。它保留每个类别、数据集或散点的原值，可用键盘展开，离线时也可查看。散点表使用 `xTitle`、`yTitle` 作为列标题，未提供时使用 `X`、`Y`。

Chart.js 使用 `defer` 加载，不阻塞正文解析。文本和数据表先显示；图表库稍后加载成功时只恢复画布，保留用户已经展开的数据表。加载失败时保留原提示和全部表格。

## 示例数据怎么生成与核对

`references/report-template.html` 里内嵌的示例报告，数字全部由 `sample/campaign-data-sample.csv` 计算得出，不手填：

```sh
python3 scripts/build_sample_data.py          # 按 CSV 重算，并经 render_report 重写模板里的示例数据
python3 scripts/build_sample_data.py --check  # 只核对；模板与 CSV 不一致时退出码为 1
```

`build_sample_data.py` 只服务于这份内置样本，不是通用分析脚本（理由见上文）。它重算总消耗、总 GMV、整体 ROI、各渠道消耗占比与 ROI、逐月 ROI，以及单笔消耗与退货率的相关系数；退货率缺失的行（CSV 第 17、26 行，行号含表头）先剔除再求平均，并在「值得关注」里注明。示例文字里的结论（如“信息流 ROI 低于盈亏线”“整体 ROI 逐月走低”）一旦与 CSV 不符，脚本会报错，不会照写。盈亏线 2.0 与退货预警线 12% 是行业经验线，不是数据本身给出的，示例里已注明。

脚本要求每行恰好 7 列，日期采用有效的 `YYYY-MM-DD` 格式，板块与渠道非空，消耗为正数，GMV 非负且总 GMV 为正，ROI 与 GMV/消耗一致，数值均有限。退货率用 `0` 到 `1` 的小数表示（`0.18` 表示 18%），空值保留为缺失，不能填 `18`。空表、观测退货率不足两行或无法计算相关性的输入会明确报错；没有缺失时，报告会说明按全部记录计算。CSV 引号未闭合等语法错误会被拒绝；行号按物理行计算，跨行记录使用该记录结束的行号。

示例中的「消耗最高的 5 笔」按全部记录排序，要求这 5 笔都有退货率。缺失记录不会先被排除再参与排名；记录不足或条件不符时，脚本会拒绝生成该结论。

模板更新使用同目录下独占创建的随机临时文件，再替换原模板。原有同名 `.tmp` 文件或符号链接不会被覆盖；写入或替换失败时会清理本次临时文件并保留原模板。

改动 CSV、模板或脚本后，运行测试：

```sh
python3 -B -I -m unittest discover -s scripts/tests -v
```

测试覆盖生成器的编码、数值边界、图表数据约束、拒绝覆盖与结构校验，样本脚本的异常 CSV、物理行号、缺失值处理和模板写入失败恢复，以及模板内嵌示例的数字与 CSV 一致。

若本机已有 Node.js（支持 `node:test`），还可运行模板脚本的回归检查，无需安装 npm 包：

```sh
node --test scripts/tests/test_template_runtime.js
```

该测试使用小型 DOM 和 Chart 替身，检查实际模板脚本的 KPI/表格数据、坐标轴名称、多数据集颜色与图例、单图失败降级、图表库延迟加载、离线图表数据表、文本安全、画布名称和次要文字对比度。它不运行浏览器，也不加载 Chart.js；真实图表出图、桌面/手机布局、键盘展开和辅助技术读屏仍需单独验收。
